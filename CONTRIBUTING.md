# Contributing

## Workflow

1. Create a branch from `main`.
2. Keep changes focused and avoid committing generated data.
3. Run the local checks listed in `README.md`.
4. Open a pull request with a short summary, screenshots for UI changes, and notes about any database behavior.

## Commit Hygiene

- Do not commit SQLite databases, upload contents, local email logs, or release ZIPs.
- Keep source changes separate from generated release output.
- Update documentation when behavior, setup, or deployment steps change.

## Security-Sensitive Changes

For authentication, file upload, email, privacy, database, or staff workflow changes, include a short risk note in the pull request.
